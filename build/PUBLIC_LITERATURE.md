# Public literature assistant

The public literature assistant is an optional, local interface layer over the
already reviewed display bundle. It is never an extraction, qualification, or
display-admission step. It accepts only `default-passages.json` rows whose
paper has both a complete reviewed identity in `bibliography.paper_items` and a
complete APA item in `bibliography.items`; reference-lane text is excluded as
factual evidence.

`POST /api/literature/preview` performs local keyword retrieval only. It returns
literal source passages, their stable IDs, SHA-256 hashes, page, complete APA
citation, printed identity and local paper link. It cannot load a credential or
make a provider request.

Generation requires both server configuration (`enabled=true`) and a request
body with `enable_model=true`. The only configured v1 provider path uses a
server-side `OPENAI_API_KEY`, the fixed HTTPS Responses endpoint, no redirects
and no automatic retries. Every request reserves against an installation-owned,
append-only ledger before egress; the default cap is USD20 and can be set only
by the local operator. A missing key, disabled generation, exhausted budget or
provider error leaves source browsing and offline preview available.

The configuration fixes the provider request to the standard service tier and
uses conservative declared price bounds (USD6 input and USD20 output per
million tokens for the selected profile, checked against the
[official OpenAI pricing page](https://platform.openai.com/pricing/) on October
31, 2026). The server refuses an oversized serialized provider request before
reservation or egress, rather than relying on source-character limits to imply
a short-context price tier. Installations may raise these bounds for their own
account terms; they cannot lower them. This is cost accounting, not a
model-quality claim.

The response schema permits the model to select only retrieved citation IDs and
requires literal support quotations. MOSAIC verifies that every support quote is
an exact, substantive substring of the source row and that each cited source
has its own support span before returning a draft. It withholds known damaged
statistic patterns rather than guessing a repair. Links, APA text,
source IDs and quoted evidence are generated by the local server, never the
model. A successful draft is still `scientifically_accepted: false`.

This component is meant for concise summaries, comparisons, literature-review
drafts and research outlines. It must disclose its limited retrieved collection
and gaps; it cannot establish completeness or scientific validity.

## Run it

After installing the public environment, use the fictional companion without
credentials:

```powershell
.venv-public/Scripts/python.exe bootstrap.py literature-demo --serve
```

Open `http://127.0.0.1:8798/assistant.html` and preview a question about teams or
coordination. This is local retrieval from invented articles. No model call
occurs, and Generate remains unavailable by default.

For generated drafts, copy `config/public_literature.example.json` to your own
configuration file, set `enabled` to `true` and choose a spending cap. Set
`OPENAI_API_KEY` in the server process's environment using your secret manager;
never put its value in the JSON file or browser. Start the same command with
`--assistant-config config/my-literature.json`. Your question and the previewed
source passages can then be sent to OpenAI when you request a draft. Review the
provider's terms and your permission to send that material before opting in.
Use one cumulative ledger per installation; changing the file is not a budget
reset. If an installation is continuing a previously authorized assistant
budget, configure that canonical append-only ledger rather than beginning a new
one. A post-processing failure recorded after a valid completed event preserves
the completed cost; an incomplete or failed request preserves its full
reservation. The shipped cap is configuration, not a grant of provider credits.

The same option works with `bootstrap.py serve --bundle <bundle.json>` and
`corpus --serve`. Preview stays available without a provider. Drafting currently
implements one model profile; it does not silently fall back to another provider.
